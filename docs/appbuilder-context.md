## Architecture Conclusions Preserved From Review

- `A1`: transaction/event identity semantics were a real Engine/modeling gap rooted in `_select_entity_id_field_name()` and are now represented through additive `identity_overrides`
- `A2`: date/type loss is a real metadata propagation bug rooted in `_infer_canonical_type()` and `_load_upstream_field_hints()` in `translation.py`, not in `sql_emitter.py`
- `A3`: the missing behavior is first-class preserved custom / non-CRUD operation support, including correct controller route generation, service semantics, and HTTP path/method preservation
- `B4`: audit emission already exists and enabling it is mechanically small in `catalog.py`, but it is still a product baseline decision
- `C9`: numeric/sequence generated-ID support was larger design work because UUID was the only first-class automatic strategy; it is now represented through additive `id_generation_overrides`

## What EdgeForge Is

EdgeForge is a contract-preserving modernization platform for legacy-heavy enterprise systems.

The goal is to:

- preserve upstream API and message/file contracts
- preserve downstream handoff contracts
- derive a stable canonical internal model
- generate a replacement application around that model
- migrate legacy behavior incrementally without breaking integrations

## Core Problem

Many enterprise replacement efforts fail because teams redesign the external contracts instead of preserving them. EdgeForge exists to make contract-preserving modernization the default path.

## Non-Negotiable Requirements

- contract-first modernization
- explicit mappings between external and canonical models
- versioned contract support
- versioned runtime profile support
- compatibility and regression coverage
- auditability and traceability of transformations
- phased migration support

## Generated Application Standards

- each generated app should build independently
- each generated app should include its own `README.md`
- each generated app should include its own `Dockerfile`
- generated application outputs should be regenerated from committed input packages/fixtures; do not commit generated app source snapshots under `GeneratedApps/`
