# Generated-App Deployment Operations Runbook

> **Scope:** deployment/operator checklist for apps generated by EdgeForge
> Engine. Generated apps are standalone Spring Boot applications and do not
> require EdgeForge, Studio, KS/KA, MCP, or TestBench at runtime.

## 1. Runtime Storage

File/XML runtime features use configurable base directories:

- `app.file-ingest.base-dir`
- `app.xml-ingest.base-dir`
- `app.xml-output.base-dir`

Defaults are isolated per app instance under:

```text
${java.io.tmpdir}/edgeforge-<bounded-context>-${APP_INSTANCE_ID:${random.uuid}}/<surface>/
```

For production, point these properties at persistent mounted volumes. Do not
depend on container `/tmp`; it may be ephemeral, size-limited, or read-only.

## 2. Network And Gateway

Generated apps ship plain HTTP with no in-application authentication — no shipped
target profile enables it (P1-5). Place them behind a TLS-terminating,
**authenticated** gateway. A merely "trusted" internal network is **not** an
accepted substitute: with no authenticating hop, every caller that can route to
the port is unauthenticated. Running without a gateway is **development-only**
operation, outside the supported v5 envelope below.

**Supported v5 posture (P1-5):** a single trusted authorization domain behind an
authenticated gateway. Every authenticated caller is trusted equally for all data
the application exposes. **The application's port must be unreachable except
through that gateway** — a caller that reaches the application directly bypasses
this entire posture, because the application itself performs no authentication or
authorization. Multi-tenant, per-user, object-level, and row-level authorization
are **not supported** until adopter-owned application authorization is implemented
and adversarially tested. See the
[generated-app security posture design](generated-app-security-posture-design.md).

**Approve the emitted HTTP surface separately.** Generic CRUD endpoints are
retained; selected OpenAPI operations do not define the entire emitted API.
Inventory the actual HTTP methods/paths and expose only explicitly approved
operations at the gateway. Unapproved CRUD, demo and batch endpoints must remain
inaccessible through it, with no direct-port bypass. Authentication alone does
not limit available methods/routes or establish business/object/tenant/row
authorization. Engine supplies neither an endpoint allowlist nor automatic
gateway configuration. Disabling a demo handler at runtime does not unregister
its mappings. See the
[2026-10-14 endpoint decision](../enterprise-readiness-roadmap.md#endpoint-boundary-maintainer-decision).

**Known input-validation limitation:** affected integer transport parameters bind
as Java `Long`; `format: int32` does not enforce signed 32-bit bounds. Engine's
range-enforcement correction is deferred post-v5. If your contract requires those
bounds, validate before business, persistence or downstream effects; gateway
authentication is not that validation. No full OpenAPI enforcement is claimed.

Rate limiting is gateway-owned. Generated apps do not enforce an in-application
rate limit; configure the shared budget at the non-bypassable gateway rather than
an independent per-replica limit.

Generated Kafka apps expose only `/actuator/health` by default. To expose metrics
and Prometheus, set
`MANAGEMENT_ENDPOINTS_WEB_EXPOSURE_INCLUDE=health,metrics,prometheus`. Enable that
opt-in only when the application port is unreachable except through the
authenticated, TLS-terminating gateway above.

## 3. Datasource Credentials

Enterprise PostgreSQL target profiles require datasource credentials to be
supplied by the deployment environment:

- `SPRING_DATASOURCE_URL`
- `SPRING_DATASOURCE_USERNAME`
- `SPRING_DATASOURCE_PASSWORD`

`SPRING_DATASOURCE_USERNAME` and `SPRING_DATASOURCE_PASSWORD` have no generated
`postgres` fallback. If either is missing, the generated app fails fast during
startup rather than silently using a default credential.

The `springboot-legacy-compatible` H2 profile remains a local/dev profile and
keeps its in-memory `sa` / empty-password settings.

## 4. Other Secrets And Endpoints

Provide the following through the platform secret/config mechanism:

- OAuth2/JWT issuer, JWK set, audience, and authority mapping values — **only
  relevant if a custom, non-shipped profile registers the internal dormant
  security emitter (P1-5); no shipped profile requires these.**
- SOAP/client endpoint URIs or other downstream system endpoints declared by the
  generated app.
- File/XML base directory overrides listed in §1.
